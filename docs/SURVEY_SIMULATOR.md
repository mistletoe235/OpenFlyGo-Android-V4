# 航测仿真与测试手册

## 1. 功能链路

1. 在小地图点击“航线”，单击地图依次添加多边形边界点。蓝色编号圆点是可编辑顶点，绿色 `S` 是首航点；点击编号点后可在地图上重新定位，或用“删除选中点”删除。任何边界编辑都会废弃旧航线，必须重新生成。
2. 在右侧航线面板设置任务名、目标面高度、GSD/高度、航空航向、安全起飞高度、起飞/航测速度、正射与倾斜各自的前向/旁向重叠率、倾斜俯角和边界外扩。GSD 与目标面上方高度双向联动；正值边距按 DJI Pilot 2 语义对测区多边形向外缓冲。
   高度可以选择“目标面上方”或“相对起飞点”；航线起点可以根据飞行器 Home/GPS 自动选择最近的蛇形航线角，也可以显式选择角点 1–4。五向任务只固定第一组起点，后续方向从上一组终点自动就近衔接；完成动作、等距离/定时拍照会随任务持久化。
   地图默认优先定位手机；连接飞行器并获得有效坐标后，可点“定位飞机”重新把规划地图置于飞行器位置。该按钮只移动地图，不申请 Virtual Stick，也不发送飞控命令。
3. “生成正射航线”创建一组 `-90°` 俯视航线；“生成五向倾斜”创建一组俯视和前、后、左、右四组倾斜航线。倾斜航线使用平坦目标面上的透视足迹和独立重叠率计算，不再复制正射矩形足迹。任务以 schema 5 保存为 WGS‑84，地图显示时转换为 GCJ‑02；规划摘要会按 Mini 2 JPEG 最短 2 秒定时拍照间隔检查航速可行性。规划和导入还会拒绝自相交、小于 1 m² 的 ROI 以及不完整或端点语义不一致的航带。
   “等距离拍照”按 WGS‑84 地面位移触发，“定时拍照”按单调时钟触发，不会再换算成距离；两种模式在执行层都强制 Mini 2 JPEG 最短 2 秒冷却。相机跟不上规划航速时 Simulator 安全门直接阻止执行。
   每次生成和 JSON 导入都会自动写入任务库，同名任务按 `v1/v2/...` 递增；“保存版本”可手动创建快照，“任务库”可恢复最近 50 个版本。恢复版本只替换规划和参数，不会启动 Simulator 或申请 VS。
   统计卡按完整航带切分 20 分钟可用架次，不会在距离拍照区间中途断开；Home/GPS 有效时，总航程和时长还会计入安全爬升、首航点转场以及返航/返回起点。Home 尚不可用时明确显示“待 Home/GPS 后计算”，不把未知转场误报为 0。
4. 先使用“预演”检查航带顺序、转场和预计采集区间。预演绝不申请 VS。
5. 在“更多 → 系统”启动 DJI 内置 Simulator，并通过现有起飞操作使 Simulator 报告 `flying`。
6. 在“更多 → 执行”执行安全预检。只有全部条件满足后，“启动仿真航线”才会申请 VS。
7. 运行中可暂停、继续或终止。暂停与终止都会归零并释放 VS；继续必须重新通过安全门。

Simulator 执行会把任务展开为显式执行段：当前位置垂直爬升到 `max(安全起飞高度, 航测高度)`，保持安全高度水平转场至首航点，再进入摄影航点。“返回航线起点”在采集后以同样的安全高度返回并下降；“悬停”归零并释放 VS。Mini 2 的 MSDK4 Simulator 不可靠支持原生 `startGoHome`，所以 Simulator 中的“返航”展开为同一安全门监管的 VS 完成段：返回飞控 Home 点上空、下降到 1.2 m 模拟起飞悬停高度、归零并释放 VS；它不伪装成真机原生 RTH 或自动降落。执行段索引和阶段写入 checkpoint schema 2，进程恢复后保持暂停，不会隐式继续。

## 2. 执行状态机

`IDLE → ARMING → RUNNING → PAUSED/COMPLETED/ABORTED`

- `ARMING`：尚未发送航线速度，只申请 VS；VS 就绪后再次检查全部门槛。
- `RUNNING`：以 DJI MSDK4 文档允许的最高 25 Hz（40 ms）读取最新飞控快照、计算 WGS‑84 位置误差并发送机体系 FRU 速度；飞控状态仍按 SDK/固件的原生回调频率更新，任务结束日志分别报告实际 VS 循环频率和新鲜飞控状态频率。水平速度使用任务速度（上限 5 m/s），安全爬升使用任务起飞速度（MSDK VS 垂直速度上限 4 m/s），其余升降保守限制为 0.5 m/s。
- 航点完成条件：水平误差不超过 1.2 m、垂直误差不超过 0.4 m、航向误差不超过 6°，并且云台俯角误差不超过 3°。
- 每个航点有按初始距离估计的 15–120 秒截止时间；超时立即终止。

## 3. 采集语义

- 相机使用单拍模式，避免依赖不同消费机固件支持不一致的定时连拍。
- 到达航带起点后立即拍第一张；沿航带按规划的地面距离间隔触发；航带终点在剩余距离有意义时补一张。
- 两次触发至少间隔 2 秒；相机命令在途或冷却未结束时，航带终点会保持悬停等待，不会丢失应补的末帧。
- 每个航点先设置任务指定的绝对云台俯角，云台未到位不会确认航点。

## 4. 自动回归矩阵

运行 `./gradlew testDebugUnitTest`。核心覆盖如下：

| 类别 | 覆盖项 | 期望 |
|---|---|---|
| 规划 | 任意/凹多边形、正射、五向倾斜、航空航向 | 航点位于 ROI，航带顺序稳定 |
| 坐标 | WGS‑84 JSON、GCJ‑02 显示转换 | 导入导出不改变任务坐标 |
| Simulator 门 | 普通飞行、未起飞、VS 未就绪、任务过长/过高/过远 | 阻止进入对应状态 |
| 跟踪 | 机体系 FRU、限速、升降和航向对齐 | 指令有界，到点输出严格零 |
| 故障 | 遥测过期、Simulator 退出、摇杆接管、航点超时、mock 注入 | `ABORT_ZERO_AND_RELEASE` |
| 采集 | 起点、距离间隔、冷却、终点、相机忙 | 不漏状态、不重复触发 |
| 恢复 | 任务和运行检查点 JSON | 运行态重启只恢复为 `PAUSED` |
| UE | WGS‑84/ENU/FRU/SI 契约 | 载荷无反向 `command` 字段 |

## 5. 设备回归矩阵

每次改动至少执行：

| 编号 | 场景 | 操作 | 必须观察到 |
|---|---|---|---|
| D1 | 普通模式 | 有任务时点“启动仿真航线” | `SIMULATOR_REQUIRED`；无 VS 申请 |
| D2 | Debug mock Simulator | 通过调试 Intent 注入，再点启动 | “调试快照不可启动控制”；日志含 `NO_CONTROL` |
| D3 | 真实 DJI Simulator 未起飞 | 预检/启动 | `SIMULATOR_NOT_FLYING` |
| D4 | 真实 DJI Simulator 飞行 | 启动短小任务 | ARMING 后 RUNNING；速度有界 |
| D5 | 运行中暂停/继续 | 点暂停，再点继续 | 暂停立即归零/释放；继续重新申请 VS |
| D6 | 运行中移动摇杆 | 任一摇杆超过阈值 | ABORTED；零速度；VS 释放 |
| D7 | 运行中关闭 Simulator | 系统页关闭 Simulator | ABORTED；后续无非零控制 |
| D8 | App 进入后台 | Home/切换应用 | ABORTED；VS 释放 |
| D9 | 任务持久化 | 生成任务、强停进程、重启 | 同一任务和参数恢复 |
| D10 | 进程异常恢复 | 运行态强制杀进程、重启 | 仅 PAUSED；不自动启用 VS |
| D11 | UE 桥 | 发任务并开遥测 | `/mission` 一次，`/telemetry` 约 1 Hz |

其中 D4–D8 必须确认 DJI SDK 确实处于内置 Simulator；不要通过 Debug mock 代替。

### 已验证基线（2026-08-03）

Mini 2 + MSDK4 内置 Simulator 的 60 m 短航带完整回归已通过：VS 固定节拍实测 `25.0 Hz`，新鲜飞控状态回调实测 `10.0 Hz`（3696 次控制循环、1477 次新状态）；航带起点与终点两张照片均收到 DJI 成功回调；完成返航段时 Home 水平误差 `0.00 m`、高度误差 `-0.30 m`，随后 VS 成功释放。

这条任务只有约 `22 m²`、单条约 `7.0 m` 航带，规划结果本来就是 `estimated_photo_count=2`。它只能证明起点/终点触发闭环，不能代表多航带拍照吞吐或外场可用性。

同一设备会话补充通过：

- D5 暂停后立即归零并释放 VS，继续时重新申请 VS；显式终止同样归零并释放。
- D8 任务运行中切到桌面，日志记录 `App 进入后台 · zero velocity · VS released`。
- App 回到前台后出现 Simulator 仍为 active、但飞控状态退化为 `GPS 0` 的不一致状态；安全门以 `GPS_UNAVAILABLE` 和起点距离拒绝启动，没有发送控制。该现象说明 Simulator 生命周期仍需单独压力回归，不能据此宣称外场可飞。

调试生命周期注意：覆盖安装 APK 会终止 App 进程，不应继续复用安装前的 Simulator 会话。若安装后 Simulator 状态与飞行状态矛盾，或 `startTakeoff` 返回 `Undefined Error`，不要连续重试；先结束本轮安装，建立一次新的飞机产品连接，再执行“启动 Simulator → 起飞”。开发时应先集中完成安装，再开始设备回归，避免把 SDK 会话失效误判为控制器问题。

## 6. 真机前分级门槛

当前代码有意不开放普通真机自动航测。进入下一阶段前必须依次满足：

1. D1–D11 全部通过并留存日志。
2. 在开阔环境完成系留/无桨台架的 VS 方向、FRU 符号和接管验证。
3. 校准具体机型相机 FOV、实际快门最短周期、云台到位误差和 GPS 漂移。
4. 增加电量、返航高度、禁飞区、最大离家距离和地形/障碍物门槛。
5. 独立代码审查后，才新增显式的真机模式开关；不得复用或放宽 Simulator 判断。

当前真机准备度审计还会硬性检查：飞机电量至少 30%、遥控器电量至少 30%、遥控信号至少 40%、GPS 至少 12 星且 LEVEL_4/5、Home 有效、飞控遥测新鲜、飞机在地面、Simulator 已关闭；同时读取飞控的返航高度、最大高度和最大半径设置，并验证能覆盖任务。首次外场任务额外限制为起点 50 m 内、总路径 1 km 内、预计 8 min 内。审计通过仍不等于自动解锁。

相机动作必须收到 DJI 成功回调；失败或 8 秒无回调会立即归零、终止任务并释放 VS，避免拍照失败后仍把任务标记为完成。

Debug 包可通过 Intent 生成以当前飞控坐标为中心的确定性 `50 x 40 m` 回归任务；该入口只生成任务，不发送控制：

```bash
adb shell am start -n com.openfly.go.v4/edu.playground.djivln.mini2.Mini2CameraActivity \
  -a com.openfly.go.v4.action.SURVEY_REGRESSION --es mode ortho
adb shell am start -n com.openfly.go.v4/edu.playground.djivln.mini2.Mini2CameraActivity \
  -a com.openfly.go.v4.action.SURVEY_REGRESSION --es mode five_direction
```
