# 航线效率与平滑控制优化设计

日期：2026-08-22

状态：设计阶段，尚未修改航线生成、Virtual Stick 控制或真机安全门。

## 1. 目标

在不降低测绘覆盖率、拍照可靠性和人工接管安全性的前提下，减少航带端点的无效减速、
停车、原地转向和重新加速，使多航带及五向倾斜任务执行更连续，并让预计时间更接近
实际飞行时间。

本设计优先解决执行层问题，不重新推翻已按 DJI Pilot 2 样本对齐的相机覆盖模型、
重叠率、边界外扩和蛇形航带几何。

## 2. 当前实现基线

### 2.1 规划层

- 根据相机参数、高度和重叠率计算航带间距及拍照间距。
- 对测区多边形按边界余量外扩，再用平行扫描线裁剪生成蛇形航带。
- 航带由 `PASS_START` 和 `PASS_END` 两个端点表达。
- 五向倾斜任务按启用的采集方向生成多组航带，并尽量从上一组终点就近衔接。
- 当前自动航向主要依据最小面积外接矩形长轴，没有把转弯次数、转场距离和起飞点
  纳入统一代价函数。

### 2.2 执行层

- Android 端以 40 ms 周期运行控制循环，目标频率为 25 Hz。
- 每次只跟踪一个目标航点，使用目标位置误差乘固定比例得到水平速度。
- 水平速度接近任务上限后限幅；接近目标时随距离线性下降。
- 航向误差独立转换为角速度，最大约 30°/s。
- 航点完成要求同时满足：水平误差不超过 1.2 m、垂直误差不超过 0.4 m、航向误差
  不超过 6°。
- 航点完成时通常先发送严格零速度，再切换到下一执行段。

这种控制方式安全、直观，适合早期闭环验证，但它把航带端点当作必须精确停稳的目标，
没有利用下一段轨迹信息。

## 3. 已观察到的问题

### 3.1 航带端点提前减速

位置比例控制会在距离端点还有数米时开始持续减速。现有日志中的典型过程为：

```text
约 2.1 m/s -> 1.8 m/s -> 0.9 m/s -> 0.14 m/s -> 航点完成
```

长直线中间可以保持任务速度，但每条航带末端都会重复损失时间。

### 3.2 转弯不连续

切换下一航带后，控制器同时进行横移、前进和航向旋转。典型航向变化为：

```text
2.6° -> 29.1° -> 60.9° -> 93.4° -> 123.8°
```

因此实际轨迹更接近“减速到零、斜移转向、重新加速”，而不是连续 U 形转弯。

### 3.3 航点条件耦合位置与航向

即使飞机已经进入水平位置容差，只要航向尚未进入 6° 容差，当前段仍不会完成。
这会在狭窄转场或强风条件下产生不必要的等待和小幅修正。

### 3.4 时间估算模型过于简化

当前预计时间主要使用距离除以任务速度，并对方向变化附加固定稳定时间和按最大角速度
计算的转向时间。它没有反映：

- 接近端点的实际减速过程；
- 转弯半径与横向加速度限制；
- 连续转弯期间仍存在的前向速度；
- 风扰、横向纠偏和拍照等待造成的实际耗时。

### 3.5 自动航向不一定是全局最高效方向

只选择多边形长轴通常能减少航带数量，但不保证总任务时间最短。例如近似正方形、凹形
测区或起飞点位于测区一侧时，另一方向可能具有更短转场、更少无效连接段或更宽松的
转弯空间。

## 4. DJI Pilot 2 对照结论

本地 `PilotDump_API29` 虚拟机中可进入 DJI Pilot 2 的区域航线创建流程。结合此前保存的
Pilot 2 WPML 样本分析，可确认：

- DJI 将测区、航带、航点航向、转弯模式和相机动作分别表达。
- 周期拍照由航带入口和出口动作控制，不为每张照片创建独立航点。
- WPML 任务能够描述协调转弯；行业机由飞控原生航点系统执行。
- Pilot 2 可对正射和倾斜航线采用不同速度，同时保持按覆盖率推导的地面拍照间距。
- 行业机的协调转弯不能直接复制给 Mini 2；V4 必须在 Android 端通过 Virtual Stick
  自己生成连续参考轨迹并闭环跟踪。

因此后续应参考 DJI 的任务语义，而不是假定 Mini 2 拥有行业机的原生曲线航点能力。

## 5. 建议的目标架构

将执行器从“航点追踪器”升级为“分阶段轨迹跟踪器”：

```text
任务几何
  -> 航带与连接段
  -> 带速度约束的参考轨迹
  -> 沿轨/横轨误差控制
  -> 机体系速度与角速度
  -> DJI Virtual Stick
```

每条轨迹应显式区分：

1. 安全爬升段；
2. 飞往首航点的转场段；
3. 航带引入段；
4. 有效拍摄航带；
5. 航带引出段；
6. 航带间转弯段；
7. 返航或返回起点段。

拍照只允许发生在有效拍摄航带，不应发生在引入、引出和转弯段。

## 6. 分阶段实施方案

### 阶段 A：线段跟踪与速度规划

目标：先改善直线稳定性和端点减速，不引入曲线转弯。

- 使用当前线段起点和终点计算沿轨进度、横轨误差和剩余距离。
- 沿轨方向保持任务速度，横向速度只用于消除横轨误差。
- 根据可用减速度计算制动距离，而不是使用目标距离乘固定比例控制整段速度。
- 对真正需要停稳的段使用梯形或 S 曲线速度规划。
- 航带末端、暂停恢复点、Home 上空和下降点采用不同的到达策略。
- 取消“所有航点一律归零”的隐式规则，只在需要停止、等待相机或安全状态切换时归零。

阶段 A 不改变转弯几何，但应显著减少直线末端过早减速。

### 阶段 B：航带引入与引出段

目标：保证进入有效测区前已经达到稳定速度、航向和云台角。

- 在有效拍摄航带两端增加可配置或自动计算的引入/引出距离。
- 引入距离至少覆盖加速距离、航向稳定距离和首张照片触发裕量。
- 在进入有效拍摄区时启动距离/时间拍照，在离开有效区域时停止。
- 引入/引出段优先布置在边界外扩区域；空间不足时降低速度或退回精确模式。
- 地图分别显示 ROI、覆盖足迹、有效拍摄航带和非拍摄连接段。

### 阶段 C：高效协调转弯

目标：在相邻平行航带之间生成连续 U 形轨迹，避免每条航带停车。

- 根据航带间距、任务速度、最大横向加速度和安全边界计算最小可用转弯半径。
- 优先使用两段圆弧加短直线，或曲率连续的三次 Bézier/缓和曲线连接相邻航带。
- 转弯段按曲率限制速度：曲率越大，允许速度越低。
- 航向参考采用轨迹切线方向，而不是直接跳变为下一航点固定航向。
- 到达判定改为“越过轨迹切换截面或沿轨进度完成”，不要求命中每个中间控制点。
- 转弯期间停止拍照；进入下一有效航带且姿态稳定后恢复。

### 阶段 D：精确与高效双模式

为避免一个控制策略覆盖所有场景，提供两个用户可理解的模式：

| 模式 | 行为 | 适用场景 |
|---|---|---|
| 精确转弯 | 航带端点减速，必要时停稳后转向 | 狭窄区域、障碍物附近、首次真机验证 |
| 高效转弯 | 使用连续轨迹和曲率限速，通常不停车 | 开阔测区、多航带、五向倾斜任务 |

建议默认保持“精确转弯”，直到高效模式完成 Simulator、UE 和开阔场地验证；验证完成后
再评估是否将高效模式作为新任务默认值。导入旧任务时不得静默改变原有执行行为。

### 阶段 E：全局航向和起点联合优化

目标：降低总时间，而不仅是缩短测区内部的几何长度。

对候选航向和四个蛇形起点计算统一代价：

```text
总代价 = 航带飞行时间
       + 航带间转弯时间
       + 起飞点至首航点转场时间
       + 完成动作时间
       + 边界/障碍物风险惩罚
```

- 对长轴方向及其附近候选角度进行离散搜索。
- 计入航带数量、转弯半径、连接段长度和起飞点位置。
- 保留用户手动指定方向和起点的能力。
- 在界面中显示“最短航程”和“最短预计时间”的差异，不把两者混为一谈。

### 阶段 F：动态预计时间

- 规划阶段根据速度曲线、转弯半径和相机等待计算预计时间。
- 执行阶段使用当前沿轨位置、实时速度和剩余轨迹重新估计。
- 分别显示当前航带/阶段剩余时间、当前架次剩余时间和完整任务剩余时间。
- 相机忙、云台等待、暂停和人工接管时间单独统计，不掩盖为飞行耗时。

## 7. 安全约束

高效模式不得以牺牲现有安全门为代价：

- 摇杆、返航键或外部飞控状态介入时仍立即暂停或终止，并发送零速度。
- 遥测过期、GPS 不可用、Virtual Stick 丢失、相机严重故障和飞控 failsafe 仍具有最高优先级。
- 轨迹生成必须检查转弯包络，不允许曲线无提示越出用户允许的边界范围。
- 转弯半径不足时必须自动降速或退回精确转弯，不能强行压缩曲线。
- 地形跟随任务必须在三维轨迹上同时检查垂直速度、净空和 DSM 覆盖范围。
- 真机首次开放时限制最大速度、最大横向加速度、最大转弯外扩和任务总长度。
- 暂停位置恢复仍应先生成安全恢复段，不允许直接跳回尚未完成的曲线中点。

## 8. 参数建议

第一版不应向用户暴露大量控制器参数，只提供：

- 转弯模式：精确 / 高效；
- 航线速度；
- 可选的最大转弯外扩或最小转弯半径高级设置。

内部参数初始建议通过仿真标定，不直接作为最终真机值：

- 最大水平加速度；
- 最大横向加速度；
- 最大减速度；
- 最大角速度和角加速度；
- 横轨误差增益；
- 轨迹前视距离；
- 进入拍摄航带所需的速度、航向和云台稳定阈值。

## 9. 验收指标

### 9.1 几何与控制

- 航带内横轨误差的 P95 和最大值。
- 航带内速度误差的 P95。
- 转弯轨迹最大外扩距离。
- 转弯过程中最大横向加速度和最大角速度。
- 航带入口达到稳定速度所需距离。
- 是否出现位置或速度命令方向突变。

### 9.2 效率

- 总任务完成时间。
- 每次转弯平均耗时。
- 低于任务速度 50% 的累计时间。
- 停止或接近停止的次数和累计时间。
- 转场距离、拍摄距离和非拍摄距离占比。

### 9.3 测绘质量

- 每条航带实际照片间距均值、P95 和最大值。
- 航带入口/出口首末照片的位置偏差。
- 实际前向和旁向覆盖裕量。
- 相机忙导致的漏拍数量。
- 转弯期间误拍数量必须为零。

### 9.4 安全与恢复

- 暂停、急停、摇杆接管后的归零延迟。
- 遥测过期到停止非零命令的延迟。
- 暂停恢复时返回恢复点的路径是否独立、安全并面向运动方向。
- App 后台、进程恢复和 Simulator 重启后不得自动继续。

## 10. 验证顺序

1. JVM 单元测试：线段投影、横轨误差、制动距离、圆弧生成和边界包络。
2. Android 纯预演：地图显示参考轨迹、速度颜色和拍照有效区。
3. UE 软件仿真：使用确定性任务对比旧控制器和新控制器。
4. DJI 内置 Simulator：验证 25 Hz 命令链路、暂停、接管和异常退出。
5. 无桨台架：核对机体系方向、航向符号和控制模式切换。
6. 开阔场地低速单航带：先验证线段跟踪和拍照距离。
7. 开阔场地双航带：验证一个高效 U 形转弯。
8. 多航带与五向任务：验证总体效率和相机覆盖。

每一阶段都应保留旧精确控制作为可回退基线。未通过上一阶段，不进入下一阶段真机测试。

## 11. 建议的开发拆分

后续实施建议按独立提交推进：

1. `test: add survey trajectory performance baselines`
2. `feat: track survey line segments with speed profiles`
3. `feat: add survey lead-in and lead-out legs`
4. `feat: add efficient coordinated survey turns`
5. `feat: expose precise and efficient turn modes`
6. `feat: optimize survey heading and start cost`
7. `feat: estimate survey time from trajectory dynamics`

每个提交都应包含对应单元测试；执行器提交还需要保留旧模式，避免一次性替换现有真机逻辑。

## 12. 预期收益

实际收益取决于航带长度、航带数量、航带间距和安全转弯半径：

- 单条长航带：提升有限，主要改善速度稳定性。
- 大型狭长测区：预计缩短约 5%–15%。
- 小型且航带密集的测区：预计缩短约 15%–35%。
- 五向倾斜任务：同一测区重复多组航带，转弯优化收益会累计。

这些数字是设计预期，不是已验证结果。最终应以同一任务、同一速度、同一 Simulator/UE
环境下的 A/B 轨迹和耗时数据为准。
