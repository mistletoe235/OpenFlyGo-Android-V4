# Android V4 公开/私有航线实现复核

日期：2026-09-27。公开基线 `8e87ee0`，私有基线 `be97080`；比较的是工作区，包含未提交修复。
本次不包含私有模型功能，不代表所有私有改动均应复制到公开版。

## 发现与修复

- 审计开始时，航线主 Activity、DJI bridge、航线执行核心和地图实现已与私有工作区一致。
  未发现 V5 那种每次高频刷新都重建航线覆盖物的问题，不能宣称 V4 有同一个地图泄漏。
  飞机/遥控器标记已有 200ms 与位移阈值限制；航线覆盖物按航段变化或显式强制刷新更新。
- 两份实现共同存在手机图像管线积压风险：只限制等待解码的请求，无法限制排入慢速存储队列的 Bitmap。
  新增共享的容量为 2 的租约预算，从解码请求前一直持有到 JPEG/文件处理结束；HIL 也使用同一预算。
  超时、拍照失败、解码异常、存储拒绝、页面销毁及迟到解码回调有对应清理。
  SDK 未返回时不会提前释放槽位；否则旧请求迟到后仍可能突破内存上限。
  预算繁忙仅跳过可选手机副本，不拒绝 DJI 实际拍照。
- Virtual Stick 的旧回调可能通过 SDK 线程上的检查后，在 UI 队列等待期间过期。
  启用/禁用及仿真相关结果改为在 UI 真正执行时再核对代次和飞控对象，避免旧控制流程继续。
- 补齐公开版相机方向测试与触发帧姿态元数据断言；保留此前主页/航线地图的屏幕常亮修复。
- 上述生产修复同时应用公开和私有 V4，没有覆盖私有工作区的其他改动。

## 不反向覆盖的差异

公开版的模型占位实现、可配置工作站地址、云端航线预览与导入权限逻辑、Release 仿地关闭、
手机照片副本默认关闭均保留。测试 fixture 路径与私有模型测试不整包复制。
手机图像预算只约束图像保存管线，不等于已经证明 SDK/地图/云端全部没有内存问题。
